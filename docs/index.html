01 / 学习困境

你缺的可能不是答案，
而是从题目走到代码的那座桥。

很多讲解告诉你“这行做了什么”，却跳过了决定先写哪一行、为什么这样写的过程。

01↗

看过答案，还是不会做

知道循环和判断分别是什么，却不知道拿到题目后先定义什么、先检查什么。

02↗

语法认识，用时不会

能说出函数名称，却不清楚参数、返回值、异常和它在这里出现的理由。

03↗

换一道题，思路就断了

记住了一份代码，却没抓住可以迁移到新题目、新项目和面试中的思考方法。

02 / 学习方法

不止解释代码，
还原代码诞生的过程。

这个 Skill 让 Codex 按学习者能跟上的顺序讲解。先建立问题模型，再看选择如何落成每一行代码。

看三种学习场景 ↗
01

把题目翻译成需求

输入是什么？要得到什么？哪些规则不能被违反？

02

重建人的设计思路

如果从空文件开始，会先定义什么，再做哪些检查和选择？

03

追踪真实执行

代入具体数据，观察分支怎么走、变量何时改变、结果怎样产生。

04

拆透函数与语法

讲清写法、输入、输出、错误，以及“为什么这里要这样写”。

05

回到独立复现

把讲解收束成可重写的步骤，让下一道题有路可走。

03 / 适用场景

从第一行代码，
到赛场和面试现场。

选择你现在的目标，看看它会把注意力放在哪里。以下是示意讲解，不是对真实题目的完整解答。

编程初学者 · Python 基础

不是只告诉你 float(input()) 是什么。

先问“为什么输入的金额不能直接拿来相减”，再拆开输入、类型转换与异常，最后让你自己写出检查逻辑。

你可以这样问

“请从设计转账程序的思路开始，解释这段代码为什么先检查金额，再修改余额。”

transfer.py示意片段
trans = float(input())
if trans <= 0:
    raise ValueError("金额必须大于 0")
balance -= trans
不是逐行翻译，而是先问

“扣钱之前，程序需要确认哪两件事？”

04 / 讲解原则

把理解留给你，
把跳步留在过去。

✦

从零基础出发数学和算法逐步推导，不默认你已经会复杂概念。

✦

说清事实与推测代码实际做了什么，与作者可能想做什么，分开说明。

✦

错误也是学习入口先指出格式、语法或逻辑问题，再解释原因和原本的设计意图。

05 / 立即开始

一次安装，
让每次提问都更接近“会写”。

这是一份可直接放入 Codex 的 Skill 文件。不需要额外安装 Python 包，也不需要配置 API。

查看 GitHub 仓库 ↗查看 SKILL.md ↗
安装步骤约 2 分钟
  1. 下载 skill 文件夹

    从仓库获取 skills/code-reasoning-teacher。

  2. 放进 Codex 的 skills 目录

    例如 Mac 上的 ~/.codex/skills/，保留文件夹内的 SKILL.md。

  3. 开始提问

    输入“帮我理解这段代码”，或明确写 $code-reasoning-teacher。
